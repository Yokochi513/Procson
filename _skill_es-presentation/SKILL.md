# es-presentation-slides

ES の文章をもとに、就活用プレゼンスライドを **HTML で見た目を確認 → OK なら .pptx に書き出す** 流れで作るスキルです。

デザインは利用者が指定するテンプレート（URL または画像）に合わせて再現します。就活生本人が発表する場面を想定し、「読みやすさ」「一言で言い切る」「余白」を最優先にします。

## 全体の流れ

1. **ES の内容を読む**（貼り付け／ファイル）。自己紹介・志望動機・自己PR に使える情報を拾う。
2. **デザインテンプレートを把握する**（→「テンプレートの扱い」）。
3. **HTML で3種類のスライドを作る**（→「3種類のレイアウト」「デザインルール」）。
4. **HTML を利用者に見せて確認してもらう。このタイミングでテキストサイズの確認をする**（→「テキストサイズの確認」）。
5. 配色・余白ルールも一緒に提示する。
6. **OK が出たら .pptx に書き出す**（→「.pptx への書き出し」）。書き出し後は必ず画像化して目視QAする。

HTML の確認をスキップして先に .pptx を作らないでください。利用者は完成イメージを見てから微調整したいので、まず HTML で合意を取るのが目的です。

## テンプレートの扱い（重要）

利用者はデザインテンプレートを **URL または画像（スクショ）** で渡してきます。

- **URL の場合**：まず WebFetch で読み取りを試みる。MiriCanvas・Canva・各種テンプレートサイトは**ログイン認証が必要で 403 になり、中身を読めないことが多い**。
- **読み取れなかった場合は、スライドを作り始める前に必ず「テンプレートのスクリーンショットを送ってください」とお願いする。** 想像でデザインを作らないこと。配色・フォントの雰囲気・レイアウト・装飾要素が分かるスクショが必要だと伝える。
- **画像が渡された場合**：その画像を読み、次を抽出してから作る:
  - 配色（背景・アクセント・文字色。分かれば HEX）
  - 見出しの装飾（マーカー、下線、図形など）
  - 本文の体裁（箇条書き記号、強調の付け方）
  - 背景のテクスチャ（無地／グラデーション／幾何学模様など）

抽出したデザインの特徴を短く言語化してから着手すると、利用者と認識を合わせやすい。

## 3種類のレイアウト

ES から次の3枚を作る。各スライドは「1スライド1メッセージ」で、要素を詰め込まない。

### ① 自己紹介
次の要素を入れる（名刺のように整理する）:
- 大学・学部学科
- 名前
- 研究内容
- 研究を通して感じたこと
- その他、現在行っていること

名前・大学を「名刺カード」的なブロックにまとめ、研究内容などを情報ブロックで並べると整理しやすい。

### ② 志望動機
- **理由の概要を一言で言い切る**（スライド中央に大きく）
- **補足説明を20字程度**添える

### ③ 自己PR
- **自分の強みを一言で言い切る**
- **強みの根拠となる補足説明を20字程度**
- **入社後の強みの活かし方を20字程度**

ES の長い文章は、この「一言＋20字補足」の形に要約する。冗長な原文をそのまま貼らない。ES が例文・伏せ字（○○大学 等）の場合はそのまま残し、本人が差し替える前提だと最後に伝える。

## テキストサイズの確認（重要）

- **本文は必ず 18px 以上**にする。
- **サイズ確認は必ず HTML プレビューを見てもらうタイミングで行う。** 作成前に「本文は何 px にしますか？」と数値で聞かない。利用者は数値だけでは実際の見え方をイメージできず、良し悪しを判断できないため。
- HTML を見せながら、現状の主なサイズ（見出し・名前・本文・強調など）を一覧で示し、「このままで良いか／もっと大きく／一部だけ調整」を選べる形で問いかける。
- 利用者が「〇〇の青文字だけ2px大きく」のような部分指定をしてきたら、その箇所だけピンポイントで調整する。

## デザインルール（配色・余白）

テンプレートに合わせつつ、次を守る。詳細な作例・具体値は `references/design.md` を参照。

**配色**
- メイン1色（構造：見出し・ヘッダー・カード）が全体の 60〜70% を占める。
- アクセント1色は強調（重要語・数値）に限定し、1スライドに1〜2箇所まで。
- それ以外は無彩色に近い色で情報の邪魔をしない。

**余白**
- スライド外周：上下約7%・左右約5%を確保。
- カード同士 0.3〜0.5インチ相当で統一。カード内側もテキストが枠に触れない余白を取る。
- 詰め込まない。余白＝読みやすさ。

作成後は必ず **配色ルールと余白ルールを文章でも提示**する（利用者が自分で編集できるように）。

## .pptx への書き出し

HTML で OK が出たら、HTML と同じデザイン・文字サイズを .pptx で再現する。**pptxgenjs** で生成する。

1. `scripts/build_pptx.js` をベースにする。ファイル先頭の `CONTENT` オブジェクトを ES の内容に、`PALETTE` をテンプレートの配色に書き換える。座標やレイアウトは3レイアウトぶん実装済み。
2. 生成:
   ```bash
   cd <作業ディレクトリ>
   npm install pptxgenjs        # 未インストールなら
   node build_pptx.js
   ```
3. **必ず目視QAする**（レンダリング崩れ・文字はみ出しの確認）。この環境は LibreOffice の一部が未導入なので、`scripts/render_qa.sh` が不足パッケージの導入と画像化をまとめて行う:
   ```bash
   bash scripts/render_qa.sh <生成した.pptx>
   ```
   出力された `slide-*.jpg` を1枚ずつ Read して、文字はみ出し・要素の重なり・余白の乱れをチェックする。問題があれば `build_pptx.js` を直して作り直す。
4. 構造検証（PowerPoint で開けるか）:
   ```bash
   python /root/.claude/skills/pptx/scripts/office/validate.py <生成した.pptx>
   ```

pptxgenjs の注意点（ハマりどころ）は公式 pptx スキル（`/root/.claude/skills/pptx/SKILL.md`）にもある。特に:
- `pres.layout = "LAYOUT_WIDE"` を **スライド追加前に**設定（13.33×7.5 インチ）。
- 色は `#` を付けない・8桁禁止（例 `"17456B"`）。
- 日本語フォントは `Meiryo` などを指定。環境にない PC では自動置換されるが、レイアウトはほぼ保たれる旨を利用者に伝える。

技術的な詳細と環境セットアップの背景は `references/rendering-notes.md` を参照。

## 成果物の渡し方

- HTML は render 表示、.pptx は attach で利用者に届ける。
- 最後に「伏せ字（○○大学等）は本人の情報に差し替えて使う」旨と、フォント自動置換の注意を添える。
- リポジトリで作業している場合は、指定ブランチにコミット＆プッシュする。生成物の中間ファイル（pdf/jpg/node_modules）は `.gitignore` に入れる。
