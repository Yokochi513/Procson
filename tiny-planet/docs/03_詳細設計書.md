## 2. 型定義（`world/manifest.ts`）
```ts
import * as THREE from 'three';

/** エリア内に置く 1 つの glb モデル */
export interface PlacedModel {
  url: string;            // 例: '/models/house.glb'（BASE_URL は実装側で付与）
  x: number;              // パッチローカル X（右, メートル目安）
  z: number;              // パッチローカル Z（前方）
  yawDeg?: number;        // 法線まわりの回転（度）。既定 0。正面が逆なら 180
  targetHeight?: number;  // 自動スケールの目標高さ（未指定なら等倍）
  collider?: boolean;     // true で建物コライダー登録（壁不可侵・屋根着地）
  colliderSize?: [number, number, number]; // コライダー箱の上書き(幅,高,奥)。未指定は AABB 自動
  shadow?: boolean;       // 影の投影/受け（既定 true）
  // 同一 url は load 結果をキャッシュし、2 回目以降は clone() で複製する（§3.5）
}

/** 木などの自動散布 */
export interface ScatterDef {
  kind: 'pine' | 'broadleaf' | string; // string の場合は glb url を散布
  count: number;
  radius: number;         // パッチ中心からの散布半径
  scaleRange?: [number, number];
}

/** 近接で開く Web ページ */
export interface PortalDef {
  url: string;
  radius?: number;        // 反応半径（既定 5）
}

/** 惑星上の 1 エリア */
export interface LandmarkDef {
  id: string;
  name: string;           // ポータル/ラベル表示名
  anchor: [number, number, number]; // 惑星中心からの方向（正規化前で可）
  models?: PlacedModel[];
  scatter?: ScatterDef[];
  portal?: PortalDef;
  spawn?: boolean;        // true のエリアを初期スポーンにする
  spawnLocal?: [number, number]; // スポーンのローカル(x,z)。既定 [0,-3]
  spawnFacingDeg?: number; // スポーン時の向き（パッチ forward からの度数）。既定 0
}
// どのエリアも spawn:true でない場合は landmarks[0]、それも無ければ惑星北極を既定スポーンとする

/** プレイヤー設定 */
export interface PlayerDef {
  model?: string;         // glb url。未指定なら桃太郎
  targetHeight: number;   // 例 1.4
  yawDeg?: number;        // 正面合わせ（既定 180）
  feetOffset: number;     // 原点→足（例 0.65）
  clips?: {               // glb アニメクリップ名の対応（任意）
    idle?: string; walk?: string; run?: string; jump?: string;
  };
}

/** 環境（空・光・大気） */
export interface EnvironmentDef {
  background: number;     // フォールバックの空色（グラデ未使用時）
  skyTop?: number;        // 空グラデ上端色（Messenger 風の空。背景大球 or シーンbg グラデ）
  skyBottom?: number;     // 空グラデ下端色
  sunColor: number; sunIntensity: number; sunPosition: [number, number, number];
  hemiSky: number; hemiGround: number; hemiIntensity: number;
  fillColor: number; fillIntensity: number;
  fog: { color: number; near: number; far: number };
  atmosphere?: { color: number; scale: number; intensity: number }; // 大気シェル
  exposure?: number;      // トーンマッピング露出
}

/** 世界全体 */
export interface WorldDef {
  planet: { radius: number; detail: number; color: number };
  environment: EnvironmentDef;
  player: PlayerDef;
  landmarks: LandmarkDef[];
}
```

## 3. glb 受け渡し規約（Meshy → ゲーム）
**この規約を守れば、マニフェストに 1 行足すだけで正しく出現する。**

### 3.1 書き出し設定（Meshy 側）
- 形式: **.glb（バイナリ・テクスチャ埋め込み）**
- 圧縮: **Draco / Meshopt なし**（デコーダ未設定のため。必要時は §8 で後付け）
- 三角形: 建物 ≤5k / キャラ ≤5k / 小物 ≤1k（超過は Decimate）
- テクスチャ: 2K 以下推奨

### 3.2 ジオメトリ規約
| 項目 | 規約 | 補足 |
|---|---|---|
| 原点/スケール | 任意で可 | ローダが「底面中心=原点・`targetHeight`」へ自動正規化 |
| 上方向 | **+Y up**（glTF 標準） | |
| 正面 | **-Z をゲーム前方**に | 合わない場合 `yawDeg` で補正（180 など） |
| 単位 | メートル目安 | `targetHeight` で最終調整するので厳密でなくてよい |

### 3.3 命名規約
- ファイル: `kebab-case.glb`（例 `red-roof-house.glb`, `player-cat.glb`）
- 役割が分かる名前にする。出典は `public/models/CREDITS.md` に追記

### 3.4 ローダ拡張（`geo/loadModel.ts`）
```ts
export interface LoadedModel { group: THREE.Group; clips: THREE.AnimationClip[]; }

// 既存 normalizeModel(object, targetHeight): Group は流用。
// 追加: アニメクリップも返すロード関数
export function loadGltf(url: string): Promise<{ scene: THREE.Group; clips: THREE.AnimationClip[] } | null>;

// 既存 placeModel(scene, patch, url, x, z, opts) は流用（建物配置・フォールバック null）。
```

### 3.5 モデルのキャッシュとクローン（重複ロード防止・必須）
データ駆動で**同じ glb を複数配置**することが多いため、url 単位でロード結果をキャッシュし、2 回目以降は複製する。
```ts
const _cache = new Map<string, Promise<{ scene: THREE.Group; clips: THREE.AnimationClip[] }>>();
async function loadCached(url: string) {
  if (!_cache.has(url)) _cache.set(url, loadGltf(url));      // 1 回だけ実ロード
  const g = await _cache.get(url)!;
  return g ? { scene: g.scene.clone(true), clips: g.clips } : null; // 複製を返す
}
```
- `clone(true)` はジオメトリ/マテリアルを**共有**（軽量）。個別に色等を変える場合のみマテリアルを複製
- SkinnedMesh（リグ付き）を複製する場合は `SkeletonUtils.clone` を使う

### 3.6 散布（scatter）のインスタンシング
同種を多数置く木・小物は **`InstancedMesh`** を基本とし、ドローコールを 1 回に抑える。
- `kind:'pine'|'broadleaf'` は `makeTree` のジオメトリを Instanced 化
- `kind:` が url の場合は glb を 1 回ロード→ジオメトリを取り出し InstancedMesh（簡略形状なら可）。複雑形状は clone 配置にフォールバック

## 4. 各モジュールのインターフェース（確定）
v1 から流用するものは現行シグネチャを正とする。新規/変更のみ詳述。

### 4.1 `world/buildWorld.ts`（新規）
```ts
export interface BuiltWorld {
  planet: THREE.Mesh;
  portalManager: PortalManager;
  spawn: { position: THREE.Vector3; facing: THREE.Vector3; feetOffset: number };
  updaters: ((dt: number, elapsed: number) => void)[]; // 水面等のフレーム更新
}
export function buildWorld(scene: THREE.Scene, renderer: THREE.WebGLRenderer, def: WorldDef): Promise<BuiltWorld>;
```
責務: 惑星生成 → 環境構築 → landmarks ループ（モデル load・配置・散布・collider・portal）→ spawn 決定。
非同期（glb ロード）を内部で待ち、構築完了後に解決。
- **ローディング UX**: 全 glb を `Promise.allSettled` で並行ロードし、完了まで DOM のローディング表示（`#loading`、プログレス可）。完了で非表示
- **モデル単体失敗時**: `console.warn` ＋ **そのモデルはスキップ**（or 半透明のプレースホルダ箱を置く）。世界全体は止めない
- **spawn 決定**: `spawn:true` のエリア → 無ければ `landmarks[0]` → それも無ければ惑星北極 `(0,1,0)`。`spawnLocal`/`spawnFacingDeg` を反映
- **updaters**: 水面など毎フレーム更新が要るものは関数を集めて `BuiltWorld.updaters` で返す（main のループが呼ぶ）

### 4.2 `player/player.ts`（再編）
```ts
export interface Player {
  object: THREE.Group;                 // = charGroup（コントローラが駆動）
  update(state: AnimationState, t: number, dt: number): void;
}
export function createPlayer(scene: THREE.Scene, def: PlayerDef): Promise<Player>;
```
- `def.model` があれば glb をロードし `normalizeModel(targetHeight)`、`-feetOffset` だけ下げて charGroup に内包
- **AnimationMixer 詳細**:
  - ロード時に `clips` 名から `THREE.AnimationClip.findByName` で各 state の `AnimationAction` を作成
  - 毎フレーム `mixer.update(dt)` を `update()` 内で必ず呼ぶ
  - state 変化時のみ `prev.fadeOut(0.15)` / `next.reset().fadeIn(0.15).play()` でクロスフェード
  - `jump` は `LoopOnce` ＋ `clampWhenFinished`（着地で idle/walk へ戻す）。他は `LoopRepeat`
  - **指定クリップが glb に存在しない場合**は、その state だけ簡易ボブにフォールバック（落ちない）
- `clips` 無し/未指定 → 簡易ボブ（移動中 0.05 / 待機 0.012、§main 現行実装）
- ロード失敗 → `createMomotaro()`（プロシージャルアニメ）にフォールバック

## 7. 受け入れ条件・検証方法
### 7.1 マイルストーン別 完了条件
| MS | 完了条件 | 検証 |
|---|---|---|
| M0 | マニフェスト 1 件から惑星＋空が出る | 起動エラーなし／型・build OK |
| M1 | プレイヤー glb が接地・移動・向き追従。クリップ再生 or ボブ | デバッグで playerRadius≈R+feet・grounded、mixer 動作 |
| M2 | 1 エリアの建物 glb が接地・壁不可侵・屋根着地・ポータル動作 | collision テスト（壁押し返し>0／屋根 push up）、E で URL |
| M3 | 複数エリアが分散表示。スポーンが指定エリア | エリアごとメッシュ数・spawn dot 確認 |
| M4 | 大気シェル・ゴールデンアワー・ポスプロ反映 | スクショ目視 |
| M5 | 60fps・サイズ予算内 | ドローコール／三角形／gzip 計測 |

### 7.2 恒常チェック（毎変更）
- `npx tsc --noEmit` 通過
- `npx vite build` 成功
- コンソール **error 0 件**（フォールバック warn は許容）
- 主要ロジックは数値検証（接地半径・押し返し・spawn 方向・三角形数）

### 7.3 計測コマンド/指標
- gzip: `gzip -c dist/assets/*.js | wc -c`（目標：初期 6MB 以下、JS は数百 KB 級）
- glb 合計: `public/models/` のサイズ合計を管理
- ランタイム: `renderer.info.render.{calls,triangles}` をデバッグ表示

## 9. 移行手順（v1 → v2 リファクタ）
1. **型と空マニフェスト追加**: `world/manifest.ts`・`world/world.ts`（既存の岡山配置を一旦そのまま WorldDef に写経でも可）
2. **buildWorld 抽出**: `main.ts` の「惑星・環境・ランドマーク・プレイヤー・ポータル生成」を `buildWorld` に移し、`main` はループと配線だけにする
3. **環境分離**: ライティング・フォグ・星・露出を `fx/environment.ts` に移管。大気シェルを追加
4. **プレイヤー分離**: glb 採用・アニメ・フォールバックを `player/player.ts` に集約（現行 cubone 差し込みを発展）
5. **エリアのデータ化**: 手作り（bikanDistrict 等）を、Meshy glb を使う `LandmarkDef` に順次置換。残すものは「テーマパック」として温存
6. **カメラ距離見直し**: `distance` を 4 程度へ（v1 の 2 は近すぎ）
7. **各段階で** tsc/build/コンソール/数値検証を実施（§7.2）

> リファクタは**機能を壊さない単位**で刻む。1 エリアを data 化して通ったら次、の順で進める。

## 10. 既知の論点・決め事
- **テーマ**: v2 は Messenger 風の汎用かわいい世界を基本とし、岡山は任意のテーマパック扱い（マニフェスト差し替えで切替可能）
- **当たり判定の深いめり込み**: 高速移動でカプセル中心が箱内部に入ると押し返しが反転する既知の弱点。通常速度では発生しないが、必要なら「移動分割×複数回 resolve」で堅牢化
- **見た目の最終判断**: 自動検証は数値まで。トーン・向き・配置の最終確認は人間の目視＋スクショで行う前提
- **音・道・草インスタンシング・ラベル UI** は M4 以降の拡張候補（本書範囲外だが拡張ポイントとして明記）
