# Tiny Planet 論理設計書（v2）

本書は [01_基本設計書](01_基本設計書.md) を受け、システムを**論理レベル**（モジュール・データ・フロー）で定義する。実装の固有名・数値は [03_詳細設計書](03_詳細設計書.md) で確定する。

## 1. システム全体構成（レイヤ）
```
┌──────────────────────────────────────────────┐
│ A. データ層（World Manifest）                 │  ← v2 の中核
│   世界定義・エリア・glb配置・ポータル・環境設定 │
├──────────────────────────────────────────────┤
│ B. 構築層（World Builder）                    │
│   マニフェストを読み、惑星/エリア/プレイヤーを生成 │
├──────────────────────────────────────────────┤
│ C. ランタイム層（Game Loop）                  │
│   入力→移動→当たり判定→カメラ→ポータル→アニメ→描画 │
├──────────────────────────────────────────────┤
│ D. エンジン基盤（v1 流用）                    │
│   Planet / Controller / Camera / Collision /  │
│   SurfacePatch / Loader / Portals / PostFX     │
├──────────────────────────────────────────────┤
│ E. アセット（public/models/*.glb：Meshy生成）  │
└──────────────────────────────────────────────┘
```
**設計原則**: 「世界の中身（A）」と「動かす仕組み（D）」を分離する。Meshy アセットの追加・差し替えは A のデータ編集だけで完結させる。

## 3. データモデル（World Manifest）
v2 の心臓部。**1 つの世界 = 1 つの WorldDef**。

### 3.1 概念図
```
WorldDef
 ├ planet            … 半径・分割・色
 ├ environment       … 空/太陽/フォグ/大気
 ├ player            … プレイヤーglb・高さ・アニメクリップ名・スポーンエリア
 └ landmarks: [      … エリアの配列
     LandmarkDef {
       id, name, anchor(惑星上の方向),
       models: [ PlacedModel{ url,x,z,yawDeg,targetHeight,collider } ],
       scatter?: { kind, count, radiusRange },   … 木などの散らし
       portal?: { url, radius },
       spawn?: bool
     }
   ]
```

### 3.2 論理エンティティ
| エンティティ | 主属性 | 意味 |
|---|---|---|
| WorldDef | planet, environment, player, landmarks | 世界全体 |
| LandmarkDef | id, name, anchor, models, scatter, portal, spawn | 惑星上の 1 エリア |
| PlacedModel | url, x, z, yawDeg, targetHeight, collider | エリア内に置く 1 glb |
| ScatterDef | kind('pine'/'broadleaf'/url), count, radius | 木などの自動散布 |
| PortalDef | url, radius | 近接で開く Web ページ |
| PlayerDef | model, targetHeight, clips, spawnLandmarkId | プレイヤー設定 |

> **座標規約**: `x,z` はエリアのアンカー接平面上のローカル座標（メートル目安）。`anchor` は惑星中心からの方向ベクトル（正規化前で可）。

## 4. シーングラフ構造（論理）
```
Scene
 ├ Planet(Mesh, BVH)                       … 地面・接地・コライダー基準
 ├ Environment
 │   ├ HemisphereLight / Directional(Sun) / Fill
 │   ├ AtmosphereShell(Mesh, backside, fresnel)
 │   └ Stars(Points)
 ├ Landmarks[]                             … エリアごとに配置
 │   └ (各glb / 散在木 / 不可視コライダー子)
 ├ CharGroup                               … コントローラが位置・向きを駆動
 │   └ PlayerModel(glb or Momotaro)        … -FEET_OFFSET だけ下げて内包
 └ (PortalPrompt は DOM オーバーレイ)
```
- **コライダー**は各建物 glb の子に不可視ボックスとして付与 → 配置変換に追従
- **プレイヤー**は CharGroup（向き・位置）と PlayerModel（見た目）を分離。アニメは PlayerModel に適用

## 5. 座標系・配置ロジック（論理）
1. 惑星中心 = 原点。地表 = 半径 R の球面（BVH 付き icosphere）
2. 重力方向 = `normalize(playerPos)` の逆。プレイヤーの up = `normalize(playerPos)`
3. エリア配置: `anchor` 方向に SurfacePatch を作る。パッチは接平面の基底（normal/right/forward）を持つ
4. モデル配置: パッチのローカル `(x,z)` → 球面 3D へ変換し、**実メッシュへレイキャストして接地**。`yawDeg` で法線周りに回転
5. 散布: フィボナッチ分布等で `count` 個を半径内にばらまき、各点を法線方向に立てる
6. 既存 2 エリア＋追加で**惑星を均等分割**するイメージ（anchor を散らす）

## 6. 状態管理（論理）
### 6.1 プレイヤー状態
- `position`(Vector3), `up`(Vector3), `facing`(Vector3), `isGrounded`, `isMoving`, `verticalVelocity`

### 6.2 アニメ状態機械
```
        speed≈0           0<speed≤run        speed>run
idle ───────────► walk ───────────► run
  ▲                 │                 │
  └─────────────────┴───── !grounded ─┴──► jump
```
- glb: クリップがあれば state→clip をクロスフェード。無ければ簡易ボブ
- 桃太郎: プロシージャルにボーン回転（v1 実装）

### 6.3 ポータル状態
- `active: PortalDef | null`（最寄りかつ範囲内）。変化時に案内 UI を出し入れ。E で `active.url` を開く

## 7. アセットパイプライン（論理フロー）
```
[Meshy AI] 生成
   │ glb(圧縮なし)書き出し
   ▼
public/models/<name>.glb 配置
   │ マニフェストに PlacedModel を追記（url,x,z,yaw,height,collider）
   ▼
buildWorld 実行時:
   loadModel(url) ─► normalize(底面中心・targetHeight) ─► surfacePatch.place ─►
   ├─ collider:true なら addBuildingCollider（registerObstacle）
   └─ scene へ追加
   ▼
（失敗時）console.warn ＋ プレースホルダ or スキップ
```
- **冪等性**: マニフェストが唯一の真実。コード変更なしでエリア・モデルを増減できる
- **検証**: 読み込み成功数・三角形合計・ドローコールをデバッグ出力

## 8. インタラクション / ポータル（論理フロー）
```
毎フレーム:
  portals.update(playerPos)
    └ 全ポータルの距離計算 → 最寄り(range内)を active に
       active 変化時: 案内UI表示/非表示
keydown 'E':
  if active: window.open(active.url)   （ユーザー操作起点 → ポップアップ可）
```
将来拡張（範囲外）: 別タブ→惑星内オーバーレイ、入場演出、戻り導線。

## 9. レンダリング / ポストプロセス（論理）
```
RenderPass(scene,camera)
  → UnrealBloomPass(高しきい値=ハイライトのみ発光)
  → TiltShift H/V(中央バンドを残し上下をぼかす=ミニチュア)
  → OutputPass(ACES トーンマッピング＋sRGB)
```
- 環境: IBL(RoomEnvironment) でやわらかい拡散光。Sun は暖色・低強度。Fill で影側を持ち上げ
- 大気シェル: 惑星より一回り大きい球を backside＋フレネルで縁を発光させ「宇宙の小さな星」感

## 10. 主要シーケンス
### 10.1 起動
```
main → buildWorld(manifest)
  → createPlanet → environment 構築
  → landmarks をループ: モデル load/配置・散布・コライダー・ポータル登録
  → player: glb load（失敗時 桃太郎）→ spawnLandmark へ配置

```
### 10.2 1 フレーム
```
dt 取得
controller.update(入力, camera)      … 移動・重力・接地・当たり解決
cameraRig.update(pos,up,facing,移動中) … 背後オートフォロー
portals.update(pos)                   … 近接案内
player アニメ更新（state 判定）
postfx.render()
```
### 10.3 入場
```
近接 → 案内UI 'E' → keydown E → window.open(url)
```

## 11. 惑星マップ（ランドマーク配置図）
惑星は球なので「平面の地図」は**正距円筒図法（緯度経度）**で表す。
**唯一の真実はマニフェストの `anchor`**。地図はそこから機械的に導出する（下式）。

### 11.1 座標規約
- 極軸 = **Y 軸**（北極 = `+Y`）
- 緯度 `lat = asin(yn)`（`-90°…+90°`、`yn` は正規化後の y）
- 経度 `lon = atan2(zn, xn)`（`-180°…+180°`、0° = `+X` 方向）

### 11.2 ランドマーク一覧（現行アンカーから算出）
| ランドマーク | anchor (raw) | 緯度 lat | 経度 lon | 備考 |
|---|---|---|---|---|
| 倉敷美観地区 | (0, 1, 0) | **+90°** | — | 北極 |
| 岡山城（烏城） | (0, 0.766, 0.643) | +50° | +90° | |
| 後楽園 | (1, 0.15, 0) | +9° | 0° | |
| 吉備津神社 | (-1, 0.1, 0.2) | +6° | +169° | |
| 白桃畑 | (0.8, -0.2, -0.55) | -12° | -35° | |
| 吉備路（備中国分寺） | (-0.3, -0.4, -0.85) | -24° | -109° | |
| 岡山駅前 桃太郎像 | (0.2, -0.5, 0.85) | -30° | +77° | **スポーン地点** |

### 11.3 正距円筒図（スキーマ）
```
経度  -180° ───── -90° ────── 0° ────── +90° ───── +180°
      ┌──────────────────────────────────────────────────┐
+90°  │                  ★ 倉敷美観地区（北極）             │
      │                                                    │
+50°  │                              ● 岡山城              │
      │                                                    │
  0°  │              ● 後楽園(0°)              ● 吉備津神社 │
      │                                          (+169°)   │
-30°  │   ● 吉備路           ◎ 駅前/スポーン                │
      │   (-109°)     ● 白桃畑(-35°)   (+77°)              │
      │                                                    │
-90°  │                （南極：未配置・拡張余地）           │
      └──────────────────────────────────────────────────┘
   ★=スポーン起点エリア  ◎=プレイヤー初期位置  ●=ランドマーク
```

### 11.4 極方向ビュー（上から/下から）
```
      ［北半球を上から］              ［南半球を下から］
            +90 美観地区                    -90 (空き)
        岡山城(+50,経90)             駅前◎(-30,経77)
     後楽園 ─┼─ 吉備津              白桃畑 ─┼─ 吉備路
     (経0)        (経169)          (経-35)      (経-109)
```

### 11.5 配置の意図・バランス
- 北半球：美観地区(北極)・岡山城・後楽園・吉備津 を高〜中緯度に
- 南半球：駅前(スポーン)・白桃畑・吉備路 を低緯度に
- 経度方向にも散らし、**惑星一周でひと通り巡れる**よう配置（既存2＋追加5＝7か所）
- v2 では `anchor` をマニフェストで持つので、**この地図はデータ変更に追従**（手で描き直さない）

### 11.6 ゲーム内マップ（任意拡張：FR-11 候補）
将来的に画面内へ「現在地つきミニマップ」を出す場合の論理：
```
各ランドマーク anchor → (lat,lon) → 2D 投影（正距円筒 or 正射影の小円）
プレイヤー位置 normalize → (lat,lon) → 同じ投影で現在地マーカー
M キーで全体マップ、常時は隅にミニマップ（任意）
```
- 実装は DOM/Canvas オーバーレイ（3D 負荷ゼロ）。マニフェストから自動生成できる
- 優先度は M4 以降（アート仕上げ段階）。必須ではない
