# Tiny Planet 基本設計書（v2 リビルド）

## 0. このドキュメントについて
本書は tiny-planet プロジェクトを **「Meshy AI で作った glb モデルを中心に据えた、データ駆動の小さな惑星探索体験」** として作り直す（v2）ための基本設計書です。
現行 v1（手作りローポリ＋岡山ランドマーク）で確立した**エンジン基盤は流用**し、コンテンツ生成を「手作りメッシュ」から「**外部 glb アセットの差し込み**」へ転換します。
詳細は [02_論理設計書](02_論理設計書.md) / [03_詳細設計書](03_詳細設計書.md) を参照。

---

## 1. コンセプト / 目的
| 項目 | 内容 |
|---|---|
| 一言で | 手のひらサイズの小さな惑星を、かわいいキャラで歩き回って探索する Web 体験 |
| 参照作品 | [Messenger (abeto.co)](https://messenger.abeto.co/) |
| v2 の主眼 | Meshy AI 製の glb を**配置データ（マニフェスト）に並べるだけで世界が組み上がる**仕組みにする |
| 長期ビジョン | 建物に入ると Web ページへ遷移する「ポータル型オープンワールド」（ハッカソン等のページ集約入口） |

### 1.1 目指す世界観（Messenger ムードボード）
Messenger の質感に「なるべく近づける」ための言語化。実装の判断基準とする。

- **スケール感**: 惑星は手のひらサイズ。重力は中心向き。地平線がすぐ丸く落ちる「ミニチュア感」
- **トーン**: やわらかいパステル／低彩度。きつい原色やギラつく金属を避ける
- **ライティング**: 拡散光ベースの穏やかな陰影。ゴールデンアワー寄りの暖色キーライト＋やわらかい影
- **フォーカス**: ティルトシフト（被写界深度）で「箱庭」感を強調
- **動き**: ゆっくり・のんびり。急がない。歩く・眺める・見つける楽しさ
- **UI**: 最小限。説明過多にしない。世界に没入させる
- **音**: 環境音（風・鳥・水）でアンビエントに満たす（v2 で追加検討）
- **形**: 角張りすぎない。丸み・なめらかさ（v1 後半でスムースシェーディング化済み）

### 1.2 v1 との関係
- **流用するもの（エンジン基盤）**: 球面重力コントローラ、三人称オートフォローカメラ、BVH 接地・建物当たり判定、surfacePatch 配置、glTF ローダ、ポストプロセス（ティルトシフト＋Bloom）、ポータル
- **作り直すもの（コンテンツ層）**: ランドマーク／キャラ／小物を**手作りメッシュ → glb アセット**へ。配置を**コード直書き → マニフェスト（データ）**へ
- **任意で残すもの**: 岡山テーマは「テーマパック」の 1 つとして温存可（必須ではない）

## 2. スコープ
### 2.1 やること（v2 対象）
- glb を**アセットマニフェスト**で宣言的に配置できる仕組み
- プレイヤーキャラを glb 化（AnimationMixer 対応、手作り桃太郎はフォールバック）
- ランドマーク（エリア）を glb 群＋散在物で構成し、惑星に分散配置
- 各エリアにポータル（建物→URL）を設定
- Messenger 寄りのアートディレクション（パレット・ライティング・大気・ポスプロ）
- 性能・サイズの予算管理

### 2.2 やらないこと（v2 範囲外）
- マルチプレイヤー
- サーバサイド／ログイン／永続化
- 物理エンジン（剛体・ラグドール等）。当たり判定は簡易カプセル押し返しのみ
- 高度な NPC AI・クエストシステム（ポータル遷移までを中核とする）
- モバイル最適化の作り込み（動作はするが最適化は後回し）

## 3. ターゲット体験と成功条件
### 3.1 体験の流れ（理想）
1. スポーン地点（玄関エリア）に降り立つ
2. WASD で歩く。カメラが自動で背後に回り、常に進む先が見える
3. 丸い惑星の上を一周しても破綻しない。坂・建物の間を抜ける
4. 気になる建物に近づくと「入る（E）」が出る → Web ページへ
5. ティルトシフト＋やわらかい光で「箱庭をのぞき込む」心地よさ

### 3.2 成功条件（受け入れ基準の要約）
- マニフェストに glb を 1 行足すだけで、惑星上に正しく接地して出現する
- 一般的なノート PC のブラウザで 60fps を維持
- コンソールエラーなし／型チェック通過／`npm run build` 成功
- 見た目が Messenger 系の「やわらかいミニチュア」に寄っている（主観評価＋スクショ確認）

## 4. 機能要件
| ID | 区分 | 内容 |
|---|---|---|
| FR-1 | 惑星 | 球状地形を生成し BVH 接地。半径・分割数・色は設定値 |
| FR-2 | 移動 | 球面重力・接平面移動。WASD＋走り（Shift）＋ジャンプ |
| FR-3 | カメラ | 進行方向の背後に自動追従（停止中はマウスで見回し） |
| FR-4 | キャラ | glb をプレイヤーに採用。アニメクリップがあれば再生、無ければ簡易ボブ。失敗時は桃太郎にフォールバック |
| FR-5 | 配置 | アセットマニフェスト（データ）から glb／散在物を球面上に配置 |
| FR-6 | 当たり判定 | 建物 glb に簡易ボックスコライダーを登録し、壁不可侵・屋根着地 |
| FR-7 | ポータル | エリア／建物に近接で案内表示、E キーで URL を開く |
| FR-8 | アート | IBL＋ゴールデンアワー光＋大気シェル＋ティルトシフト＋Bloom |
| FR-9 | スポーン | マニフェストで指定したエリアを初期位置にする |
| FR-10 | デバッグ | 開発時にコア状態を `window.__planet` に公開（本番無効） |
| FR-11 | マップ | 惑星のランドマーク配置図（緯度経度）。任意でゲーム内ミニマップ（現在地表示）。[02_論理設計書](02_論理設計書.md) §11 |
| FR-12 | 仲間 | 犬・サル・キジを配置。会話→岡山クイズ正解で仲間化し、おとも風に追随（[04](04_ゲームプレイ設計_桃太郎ストーリー.md)） |
| FR-13 | 会話/クイズ | DOM オーバーレイの会話・3択クイズ。正誤で加入分岐 |
| FR-14 | 敵（鬼） | 鬼ヶ島エリアで追跡。接触で分岐（仲間<3=ゲームオーバー／==3=ボス戦） |
| FR-15 | ボス/エンディング | 3匹揃い接触で自動カットシーン→鬼退治→エンディング |
| FR-16 | ゲーム状態 | explore/dialogue/boss/gameover/ending の状態マシン。ゲームオーバーはスポーン再開 |

## 5. 非機能要件
| 区分 | 目標 |
|---|---|
| 初期ロード | 6MB 以下（Messenger 5.7MB を参考）。glb 合計の上限を管理 |
| フレームレート | 一般的なノート PC・ブラウザで 60fps |
| ドローコール | 1000 前後を上限の目安（超える場合は InstancedMesh / マージ） |
| 1 モデルの三角形 | 建物 5k 以下、キャラ 5k 以下、小物 1k 以下を目安 |
| 依存 | 追加 npm パッケージは原則禁止（three / three-mesh-bvh / vite のみ） |
| 対応 | デスクトップ Chrome/Edge/Firefox 最新。WebGL2 |

## 6. 技術スタック
- 言語: TypeScript / ビルド: Vite
- 3D: Three.js / 当たり: three-mesh-bvh（BVH レイキャスト・shapecast）
- アセット: **Meshy AI** で生成した glb（圧縮なし＝Draco/Meshopt 不使用）。`public/models/` に配置
- ポスプロ: three 標準（EffectComposer / UnrealBloom / TiltShift / OutputPass）

---

## 7. アセット方針（Meshy AI 中心）
- **入手**: Meshy AI でテキスト/画像から生成 → **.glb（圧縮なし）**で書き出し
- **配置**: `public/models/` に置き、マニフェストから URL 参照
- **正規化**: ローダ側でバウンディングボックスから「**底面中心=原点・指定の高さ**」へ自動スケール（モデルの原点ズレを吸収）
- **規約**: 正面 **-Z**（ゲーム前方）に合わせる。逆なら `yawDeg:180`。詳細は [03_詳細設計書](03_詳細設計書.md) §3
- **ライセンス**: Meshy 生成物・流用素材の利用条件を `public/models/CREDITS.md` で管理
- **トーン合わせ**: Meshy のテクスチャが派手な場合、マテリアルの彩度・粗さを調整（envMapIntensity / 色補正）して Messenger 寄りに寄せる

---

## 8. リスクと前提
| リスク | 対策 |
|---|---|
| Meshy の glb がハイポリ／重い | 三角形・サイズ予算を設定。超過時は簡略化（Decimate）やローダで間引き |
| glb の向き・スケール・原点がバラバラ | ローダで自動正規化＋ `yawDeg` で吸収 |
| Draco 圧縮で読めない | 「圧縮なし書き出し」を規約化。必要なら DRACOLoader を後付け |
| 派手なテクスチャで世界観が崩れる | マテリアル後処理（色味・粗さ）で統一。ライティングで馴染ませる |
| ドローコール増で 60fps 割れ | InstancedMesh／ジオメトリマージ／エリア単位の表示制御 |
| 見た目の最終判断は人間が必要 | スクショ共有＋短い目視フィードバックループを前提にする |

## 9. マイルストーン
1. **M0 基盤整理**: v1 のエンジンを「データ駆動」へリファクタ（マニフェスト読み込みで世界を構築）
2. **M1 プレイヤー glb 化**: Meshy キャラ＋アニメ（または簡易ボブ）。スポーン・カメラ確定
3. **M2 1 エリア構築**: Meshy 建物 glb を 1 エリアに配置＋当たり判定＋ポータル（縦の体験を通す）
4. **M3 複数エリア**: マニフェストでエリアを増やし惑星全体へ分散
5. **M4 アート仕上げ**: 大気シェル・ゴールデンアワー・ポスプロ調整・環境音
6. **M5 最適化**: インスタンシング・サイズ削減・60fps 確認

各マイルストーンの完了条件・検証は [03_詳細設計書](03_詳細設計書.md) §7 を参照。
