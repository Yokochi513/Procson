# ES → 就活スライド ジェネレーター

エントリーシートの文章と、参考デザイン（テンプレートのURLまたはスクショ）から、
**①自己紹介／②志望動機／③自己PR** の3種類のスライドを作る。
成果物は「HTMLプレビュー（自己完結）」＋「PowerPoint（.pptx）」の2形態。

デザインの一貫性は [design-system.md](references/design-system.md)、各スライドに入れる
内容と文字数ルールは [content-guide.md](references/content-guide.md) に集約している。
編集前に必ずこの2つを読む。

## 基本方針

1. **デザインは利用者の希望に合わせる**。いきなり既定デザインで作らず、まず「どんなテンプレートを参考にしたいか」をヒアリングして決める（下記フェーズ1）。テンプレの実物（URL/スクショ）が示されたら、読み取れないなら勝手に作らずスクショを依頼する。
2. **本文はESから作る**。事実（大学名・エピソード・数値）を創作しない。ESに無い固有情報は「○○大学」等のプレースホルダのまま残し、ユーザーに差し替えを促す。
3. **HTMLで合意 → pptx**。見た目のOKをもらう前に .pptx を作り込まない。
4. **1スライド=主張＋短い補足**。長文をそのまま貼らず、content-guide.md の文字数に圧縮する。

## 手順

### フェーズ0：入力を集める

- **ES**（.md/.txt/.docx/貼り付けテキスト等）の場所を確認して読み込む。ここから各スライドの本文を作る。
- 出力先や希望（氏名を実名に、等）があれば拾う。
- 参考デザインの希望は**フェーズ1でヒアリングする**（この時点で示されていれば拾っておく）。

### フェーズ1：参考にするデザインテンプレートをヒアリングして決める

デザインは利用者の好みに合わせる。**作り始める前に、まず「どんなテンプレートを参考にしたいか」を聞く。** 既にテンプレの当てがある人と、無い人で分岐する。`AskUserQuestion` を使い、推奨案を添えて1問ずつ確認する。

1. **入口の質問**：「参考にしたい具体的なテンプレート（URL/スクショ/既存ファイル）はありますか？ それとも、好みを教えてもらってこちらで方向性を提案しますか？」
2. **(A) 具体的なテンプレがある場合**：
   - URLなら `WebFetch` で配色・フォント・レイアウト・装飾を読み取る。
   - **読み取れない場合（403／ログイン必須／JSキャンバス等）は、作り始める前に必ず「テンプレートのスクリーンショットを送ってください」と依頼する。** 憶測でデザインを決めない。
     - もらうと助かる画像：表紙（配色・フォントの雰囲気）／本文スライド1〜2枚（見出しと本文の配置・装飾）／配色が濃く出ている部分。
   - スクショが来たら、そこから **配色（HEX）・見出しの表現・装飾の使い方・全体トーン** を言語化する。
3. **(B) 当てが無い／おまかせの場合**：好みを数問ヒアリングして方向性を決める。各質問に**推奨案（既定）を添える**（下記「ヒアリング項目」）。答えが出そろったら、決めた方向性を一度**言葉で要約して合意**を取ってから次へ進む。
4. 決めた内容を design-system.md の「配色」変数に落とす（既定のネイビー系から、必要な色・トーンだけ差し替える）。方向性が固まらない場合は既定（ネイビー×ブルー×ホワイトのコーポレート調）で仮組みし、HTMLプレビュー（フェーズ3）で微調整する。

#### ヒアリング項目（Bのとき。`AskUserQuestion` で1問ずつ、推奨案つき）

- **全体トーン**：コーポレート堅め（推奨） / クリエイティブ・カジュアル / シンプル・ミニマル。
- **配色の方向性**：ネイビー系（信頼・堅実／推奨） / モノトーン（洗練） / 暖色系（親しみ） / 企業のブランドカラー指定あり（→ HEX を聞く）。
- **業界・職種の雰囲気**：応募先の業界（IT・金融・メーカー・広告 等）。堅さ／自由度の判断材料にする。
- **フォーマット指定**：企業指定のテンプレやサイズ指定の有無（無ければ 16:9）。

> ヒアリングは目的達成に必要な範囲で簡潔に。ユーザーが「おまかせで」と言えば既定案で進め、プレビューで調整する（質問攻めにしない）。

### フェーズ2：内容を作る

- content-guide.md に従い、ESの文章を各スライドの項目に圧縮する。
  - ①自己紹介：大学／学部学科／氏名／研究内容／研究を通して感じたこと／現在行っていること
  - ②志望動機：理由を**一言で言い切る**＋補足（約20字）
  - ③自己PR：強みを**一言で言い切る**＋根拠（約20字）＋入社後の活かし方（約20字）
- ESに具体エピソードが薄い項目は、ESの範囲で言い換えるにとどめ、創作しない。

### フェーズ3：HTMLプレビューを作って確認してもらう

1. `assets/slide-template.html` を土台にコピーし、フェーズ1の配色（`:root` の CSS変数）とフェーズ2の本文を反映する。強調語は `accent`／`em` クラスで囲む。
2. できたHTMLをユーザーに提示し（レンダリング表示）、**配色ルールと余白ルールも併記**する（design-system.md の要約でよい）。
3. 「まずHTMLで見た目を確認 → OKなら .pptx」の順で必ず確認を取る。修正はHTML側で回す。

### フェーズ4：PowerPoint（.pptx）に書き出す

1. `pip install python-pptx`（未導入なら）。
2. `assets/build_pptx.py` をコピーし、上部の `THEME`（配色）と `DATA`（本文）を**HTMLと同じ内容**に揃える。本文中の `**強調**` がアクセント色になる。文字サイズ全体を変えたいときは `SIZES` を触る。
3. `python build_pptx.py <出力先.pptx>` で生成。
4. 生成物を渡す。この環境では LibreOffice によるpptx→画像プレビューが不安定なため、**PowerPoint/Googleスライドでの最終確認をユーザーに依頼する**。フォントが無い環境では既定ゴシックに置換される旨も伝える。

### フェーズ5：整合と後始末

- **HTML と pptx の内容・配色・文字サイズを必ず一致させる**（片方だけ直して不整合を残さない）。
- サイズ変更でスライドに収まらなくなったら、**文字を小さくする前に文を短くする**（content-guide.md）。それでも溢れる場合のみ、余白圧縮→サイズ調整の順。

## 収録ファイル

| ファイル | 用途 |
|----------|------|
| `references/design-system.md` | 配色・余白・タイポグラフィのルール（HEX一覧・サイズ表） |
| `references/content-guide.md` | 3レイアウトの項目定義と文字数ルール |
| `assets/slide-template.html` | HTMLプレビューの土台（そのままブラウザで開ける） |
| `assets/build_pptx.py` | `THEME`/`DATA` を差し替えて .pptx を書き出すスクリプト |

## よくある調整

- **配色を変える**：design-system.md の HEX を決め → HTMLの `:root` と build_pptx.py の `THEME` を同じ値に。
- **全体の文字を大きく/小さく**：build_pptx.py の `SIZES`、HTMLは各 `font-size`。※大きくして溢れたらまず文を短く。
- **氏名・大学を実名に**：プレースホルダ（○○大学 等）をESの実データに置換。
- **別のESで作り直す**：フェーズ2からやり直せば、同じデザインで中身だけ差し替えられる。
