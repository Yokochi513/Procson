# 日記から見つけるES自己PR・ガクチカの種

日記に書かれた日常の出来事（アルバイト・サークル・勉強・友人関係など）から、ES（エントリーシート）でそのまま使える自己PR・ガクチカの「種」を発掘し、STAR形式で整理するスキル。目的は、**本人がまだ言葉にできていない・気づいていない強みを言語化すること**であり、話を大きくして「盛る」ことではない。

## 目的・スタンス

- **目的**：日記から、ESで使える自己PR・ガクチカの種を見つける。
- **「盛る」のではなく「気づいていない強みの言語化」**。日記に書かれた行動の中に、本人がすごいこととして書いていなくても、就活で評価される強み（主体性・協調性・対応力・継続力・傾聴力など）が隠れていることがある。それを見つけて名前をつけるのが仕事であり、実際に起きていないことを付け足すのは仕事ではない。
- **日記にない実績や数字は絶対に作らない。** 「売上を〇%改善した」「〇人をまとめた」のような、日記に書かれていない具体的な成果・数字は書かない。数字が無い場合は「日記に数字の記載がないため、実際の数値は本人に確認する必要がある」と正直に注記する。
- ES1文サンプルは**清書された模範解答ではなく「種」**。あくまで本人が今後肉付けするための下書きの出発点として提示する。

## 入力

就活生が書いた日記（Markdownやテキストなど、日付ごとに区切られた日々の記録）。1日1〜数行の短い記述の集合であることが多い。

## 処理手順

### ステップ1：強みが表れているエピソード候補を抽出する

日記の中から、以下のような「強みが行動として滲み出ている」記述を優先的に拾う。単なる予定の記録（「今日は特に何もなかった」等）は対象外とする。

目印になる表現の例と、対応しやすい強みラベルの例（あくまで例。実際の記述内容に基づいて判断すること）：
- 自分から動いた・引き受けた → 主体性・行動力
- 人と協力した・教えた・巻き込んだ → 協調性・指導力
- 予期しない事態に対応した・乗り切った → 対応力・柔軟性
- 同じことを地道に続けている（バイト・サークル・勉強など複数回登場） → 継続力
- 人の話をよく聞いて考えを変えた・工夫した → 傾聴力・課題解決力

1つの日記に複数の候補がある場合、**性質の異なるものを3〜5件程度**選ぶ（同じ強みラベルばかりに偏らないようにする）。時系列で複数回登場する行動（例：バイトでの成長が複数の日にわたって書かれている）は「継続力」の根拠として横断的にまとめてよい。

### ステップ2：エピソードごとに「強みラベル／根拠／STAR／ES1文サンプル」を作る

各候補について、以下の4項目を作る。

1. **強みのラベル**：日記の行動から抽出できる強みを一言で（例：主体性、対応力、継続力、協調性、指導力 など）。抽象的すぎる／根拠のない美辞麗句（「リーダーシップがある」等）にならないよう、必ず日記の具体的な行動に紐づける。
2. **日記中の根拠（引用）**：該当箇所を日記から正確に引用する。改変・誇張しない。
3. **STAR**：
   - **状況（Situation）**：日記に書かれている場面の設定。書かれていない前提は補わない。
   - **課題（Task）**：その場面で何が求められていたか。日記に明記されていなければ、状況から素直に読み取れる範囲に留める。
   - **行動（Action）**：日記に書かれている本人の具体的な行動。
   - **結果（Result）**：日記に書かれている範囲の結果・変化のみ。数字や成果が書かれていなければ「（日記に成果の記載なし。本人に確認が必要）」と明記し、勝手に作らない。
4. **ES1文サンプル**：上記を踏まえた、ESの冒頭に使えそうな1文（60〜100字程度が目安）。「私は〇〇という強みがあります。〇〇の経験を通じて培いました。」のような形式で、日記にある事実の範囲内で作成する。誇張表現（「圧倒的な」「劇的に」等、根拠のない強調語）は避ける。
   - **重要：S（状況）・A（行動）・R（結果）に明記されていない感情・学び・心情の変化を、ES1文サンプルの中で勝手に補完しない。** 例えば日記が「パニックになりかけたが乗り切った」なら「慌てず対応した」と書き換えない（動揺した事実と矛盾する）。日記が行動の記述だけで学び・気づきに触れていないなら、「〜という姿勢を身につけました」のような学びの断定は書かず、「（この経験から得た学びは日記に記載がないため、本人に要確認）」と正直に注記する。ES1文サンプルを作る前に、STARのどの要素にも書かれていない感情・学びを付け足していないか必ず見直すこと。

### ステップ3：出力フォーマット

Markdownで、候補ごとに見出しを立てて出力する。

```
## 強みの種：〈強みラベル〉（Day◯・日付）
> 日記の根拠：「〜」

- **状況（S）**：...
- **課題（T）**：...
- **行動（A）**：...
- **結果（R）**：...（日記に記載がなければその旨を明記）

**ES1文サンプル**：「〜」
```

すべての候補を出力したあとに、最後に必ず次のセクションを追加する。

```
## イチオシのガクチカ候補

〈候補名〉を推す。理由：〜（なぜこれが最もES映えするか、他の候補と比べて何が強いかを一言で）

## さらに深めるための質問3つ

1. ...
2. ...
3. ...
```

**イチオシの選定基準**（優先順に適用）：
1. **STARの4要素が最も具体的に埋まっている**（結果まで日記から読み取れる、または本人が容易に補完できる）
2. **業界・職種を問わず汎用性が高い強み**（対応力・主体性・継続力など、多くの企業で評価されやすいもの）
3. **他の候補と重複しない、独自性のあるエピソード**

**深めるための質問3つ**は、イチオシ候補の中で日記だけでは分からない部分（特に数字・結果・周囲の反応など）を本人に思い出させるための質問にする。模範解答は書かない。

## 出力時の注意

- 強みラベルは日記の行動に基づいて自然に導出されたものにする。「リーダーシップ」「グローバル思考」のような、根拠の薄いバズワードを当てはめない。
- 数字・実績を聞かれても、日記にない場合は絶対に創作しない。「（要確認）」と明記して本人に委ねる。
- **ES1文サンプルを書き終えたら、その文に「日記のS・A・Rのどこにも書かれていない感情・学び・心情」が紛れ込んでいないか必ず見直す。** 特に、日記が否定的・中立的な表現（「パニックになりかけた」「難しい」など）のときに、それを都合よく肯定的な表現（「慌てず」「乗り越えた」など）に書き換えていないか要注意。
- ES1文サンプルはあくまで「種」であり、そのまま提出用の完成文として扱わないよう、出力の冒頭か末尾で一言添える。
