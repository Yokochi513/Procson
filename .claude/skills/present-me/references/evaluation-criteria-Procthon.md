# 評価観点シート（記入用）

発表が**採点・審査される**場合（コンテスト、ハッカソン、ゼミ発表、社内審査、選考など）に、その**評価観点（採点基準・ルーブリック）**を書き出すシートです。`present-me` スキルはここに書かれた観点を「発表資料が必ず満たすべき要件」として扱い、各観点に対応するスライドを用意し、最後にカバレッジ（全観点が資料に落ちているか）を検証します。

## 使い方

1. このファイルを**コピー**して、ネタ元と同じ場所に `評価観点_<テーマ>.md` などの名前で保存する。
2. 分かる範囲で下記を埋める（配布ルーブリックがあればそれを転記する）。不明な項目は「未記載」でよい。
3. 記入し終えたらファイルの場所を Claude に伝える。以降、この観点に沿って資料を作成する。

---

## 1. 発表の場・評価者

- **発表の場**：AIを使用したハッカソンの成果発表
- **評価者**：主催元の本部長、社長
- **採点方式**：審査員の主観
- **持ち時間・形式**：AIをどのように使用したのか:10分, 成果物:5分, スライドあり

## 2. 評価観点（採点基準）

観点ごとに1行埋める。**配点（重み）が大きい観点ほど、資料で厚く扱う**ことになる。IDは自動採番の目安（`EV-1`, `EV-2`, …）。

| ID   | 評価観点           | 評価される内容（何を見られるか）                                   | 配点/重み | 高評価の条件（何があれば満点か）                                                                       |
| ---- | ------------------ | ------------------------------------------------------------------ | --------- | ------------------------------------------------------------------------------------------------------ |
| EV-1 | 再現性             | 第三者が同じ手順・プロンプト・判断基準で近い結果を再現できる       | 高        | AIを利用する上で、チームメンバーが手順やプロンプトで同じことを再現できる仕組みや取り組みができているか |
| EV-2 | 汎用性             | 作成したプロンプトや進め方が、別のお題やプロジェクトにも活かせるか | 高        | どんなお題でも使用できる                                                                               |
| EV-3 | コミュニケーション | チーム内で情報共有などがきちんとできていたか                       | 中        | 情報共有がきちんとできており、メンバーが何をしているのかわからない状態が存在しない |

## 3. 特に重視される観点・地雷

- **最重視される観点**：汎用性の観点
- **減点・NGになりやすい点**：プロセスが書かれていないこと
- **審査員が抱きがちな疑問／過去の指摘**：チームとしてどのような方針でどのように使用する計画を立てたか
